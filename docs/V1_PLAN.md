# V1 机器人计划书

## 1. 目标

V1 只做三大板块：

- 体育
- 加密
- 天气

V1 的目标不是一次性做出“全站通吃”的自动机器人，而是先做出一套可扩展的
统一内核，并让三类策略可以独立研发、独立回测、独立开关、独立部署。

## 2. V1 范围

### 体育

- `sports.anchor`
  赛前赔率锚定。用外部赔率、Elo、Poisson、伤停和首发信号估计公允概率。
- `sports.live`
  赛中胜率更新。优先支持足球赛前和 NFL/NBA 赛中。

### 加密

- `crypto.surface`
  同资产同到期多 strike 概率曲面拟合与相对价值。
- `crypto.maker`
  maker-first 做市与库存倾斜。

### 天气

- `weather.ensemble`
  多模型集合预报概率定价。
- `weather.threshold`
  同城市同日期多阈值价格一致性检查。

## 3. 明确不做

- V1 不做政治、娱乐、科技等其它板块。
- V1 不做基于 LLM 的主导型新闻策略。
- V1 不做高耦合的“超级总策略”。
- V1 不做没有 replay 的直接实盘。

## 4. 统一架构原则

- 所有策略都只消费标准化后的市场、订单簿、外部特征和仓位状态。
- 所有策略都只输出标准化信号，不直接下单。
- 执行层只处理报价、下单、撤单、库存和成交回报，不做预测。
- 风控层独立审批所有信号和订单，不接受策略层直接越权。
- 外部 API 接入必须放在 adapter 层，不允许散落在策略代码里。

## 5. 交付阶段

### P0. 基础骨架

- 仓库初始化
- 模块边界冻结
- 统一类型、接口、配置模板
- 文档和测试目录搭建

### P1. 研究与回放

- Sports/crypto/weather 的样本市场抓取
- 归一化事件模型
- Replay 管道
- 每类策略的离线评估脚本

### P2. Paper Trading

- 连通 Polymarket 只读数据与模拟订单簿
- 输出 paper fills、PnL、risk rejects
- 独立记录每个策略的结果

### P3. Shadow Trading

- 接入真实执行路径但不提交实单
- 核对 paper/shadow 偏差
- 校验费用、延迟、撤单时序

### P4. Small Live

- 仅启用单类别单策略
- 小额度上线
- 达标后再逐步扩容

## 6. 成功标准

- 每个类别可以单独启停而不影响其它类别。
- 任何策略变更都可以通过本类别配置和测试独立验证。
- 任一策略失败不会中断其它类别执行。
- V1 的 live 入口默认关闭，必须通过显式配置开启。
